# 白区库存管理 · 库位看板

白区（上下工序之间的产品停放区）的**「记一笔」实时流水账 + 看板**。
入库/出库/转移随手记一笔，看板实时回答三个问题：**该区域有什么产品、有多少件、停了多久**。

看板版式仿白区库存看板（区域分节 + 库位网格 + 批次迷你格）。技术栈与 huaen 一致：Vue3 + Vite + Element Plus / Express + tsx / JSONL 只追加台账（零原生依赖，复制 `backend/data` 目录即备份）。

## 快速开始

**日常使用：双击项目根目录的 `start-board.bat`**（已在运行则直接打开看板；首次运行自动装依赖；3 秒后自动弹浏览器）。停止用 `stop-board.bat` 或直接关掉启动窗口。开机自启：把 `start-board.bat` 的快捷方式放进 `Win+R → shell:startup` 文件夹。

手动方式（三步）：

```bash
npm run setup    # 首次：安装前后端依赖
npm run build    # 首次：构建前端（改动前端代码后重跑）
npm start        # 启动，浏览器打开 http://localhost:8792
```

启动后控制台会打印局域网地址，车间大屏 / 其他电脑 / 手机直接访问该地址即可（看板每 30 秒自动刷新）。

**钉钉工作台/手机访问**：把 `http://内网IP:8792/#record` 配到钉钉工作台入口，打开即自动弹出「记一笔」录入（页面已做手机适配：弹窗 94% 宽自适应、按钮铺开、网格两列）。前提是手机与看板所在电脑在同一内网。

**手机扫码（钉钉内，10/3 上线）**：手机钉钉打开看板后可用「扫码」按钮（钉钉原生扫码，支持二维码/条形码）：

- 看板头部「扫码」：先弹操作类型选择——选**入库/出库/转移** → 自动打开「记一笔」**连续扫码填表**（扫库位码选定库位、扫产品码带出图号，人工核对数量后提交）；选**查询** → 扫**库位二维码**弹该库位批次明细、扫**产品条码**（码内容=图号）打开产品查询显示库存分布
- 「记一笔」表单：库位 / 目标库位 / 产品图号输入框旁的相机按钮，扫一下自动填充（扫产品码后自动选停放最久的批次）
- **库位二维码标签**：设置页 →「生成库位二维码标签」→ 打印裁开贴到现场库位（二维码内容=库位号）

一次性配置（设置页钉钉区新增两项，AppKey/AppSecret 复用现有）：**企业 CorpId**（钉钉管理后台 → 企业信息）+ **应用 AgentId**（钉钉开放平台 → 应用详情）。填好保存即用，不填不影响同步功能；详见部署手册「手机扫码配置」。

**当前已内置演示流水**（17 笔，批次、库位均为虚构），正式启用前清掉：

```bash
npm run reset          # 清空流水台账（保留库位登记和阈值）
npm run reset -- --all # 连库位、阈值一并恢复默认
```

## 日常使用（仿白区「记一笔」）

点看板头部绿色「**记一笔**」按钮，弹窗里三步完成：

1. **操作类型**：入库 / 出库 / 转移
2. **入库**：选库位 → 填产品图号 → 选操作时间（**批次号由该时间自动生成，格式 MMDD-HHmm**）→ 件数；**出库**：选有货库位（即现场小区域，如 4C2）→ 选产品图号 → 批次默认「自动·先进先出（可跨批）」直接填总件数（**该库位多批按停放最久优先一次扣足**，如 4 批各 10 件出 35 件一次完成，成功后显示拆批明细；也可指定某一批精确出库）；**转移**：选有货库位 → 选产品图号 → 选批次（默认已选停放最久，先进先出）→ 件数 → 目标库位
3. 填录入人（谁经手谁署名）→ **记入台账**，看板即时刷新

规则要点：记账单元 = 库位 × 产品图号 × 批次（按操作时间自动生成）；同图号同批次再入库是累加件数、停放不重算；转移后在新库位停放重新起算；**跨批出库按「停放最久优先」在所选库位（小区域）内自动拆批扣减，台账/钉钉流水按批拆多行（同一操作时间，可整体追溯）**；出库/转移超出现有库存会被拒绝。

**双向打通 + 镜像模式**：钉钉「出入库流水表」和网页端都是录入口。网页记一笔会自动回写钉钉流水（失败不阻塞、下次同步补写；转移拆成出库+入库两行）。**镜像模式（默认开启）**：每次同步后看板与钉钉表格完全对齐——表格里删行/改行，最迟 2 分钟内在看板生效；网页端刚记未落表的笔有 10 分钟保护期。网页端用的产品图号从钉钉表选项中选取（583 个图号可搜索）。

## 第一期 · PDA 扫码录入（MES 模号唯一码）

MES 二维码扫出的是 **模号唯一码**（MO 码，默认格式 `^MO\d{12}$`，如 `MO261121000005`），**一码 = 一件产品**，一码对应一个物料图号。

1. **导入 MES 清单**（设置页 →「MES 清单导入」）：从 MES 导出清单整表复制（含表头）粘贴，或上传 `.xlsx`。按表头名识别列，至少需「模号唯一码」「物料图号」，同码覆盖更新，返回 新增/更新/未变/跳过 数；下方可按码/物料编号/名称/图号/模号/单据编号查询并手工修正。对照表存 `data/mo-map.json`。
2. **PDA 录入页 `#pda`**（`http://内网IP:8792/#pda`，或顶栏「PDA录入」）：大字号大按钮，扫码框始终聚焦（硬件扫码头键盘输入 + 回车，连扫自动排队不丢码）。
   - 选 入库 / 出库 / 转移 → 扫**库位码**定库位（转移：第二个库位码 = 目标库位）→ 连续扫 **MO 码**，按图号分组计数，显示物料名称/图号/模号，可删误扫，重复扫同码会提示；
   - 入库时已在库的码直接拦下；出库/转移时扫的码必须在当前库位在库；
   - 图号对不上钉钉表选项时（或码未导入）弹出钉钉图号搜索选择，**选一次后记住**（`data/drawing-alias.json`）；
   - 录入人存本机；**一键提交**（每个图号一笔，带 MO 码清单与 requestId，网络抖动重试不会重复入账），成功后清空列表、保留库位；
   - 若设置开启了「锁定录入人」，PDA 提交会被拒并明确提示（PDA 登录属第二期）。
3. **图号对齐**顺序：钉钉选项全文 → 去掉括号部分后唯一匹配（`92056593(6545、6563)` ↔ `92056593`）→ alias 表 → 都没有则用原文并请人工选。钉钉选项会缓存到 `data/dt-products.json`，钉钉临时不可用时照常对齐。
4. **一件一码防重**：台账事件新增可选 `moCodes`，MO 在库索引由台账重放得出（入库加入、出库移除、转移移动）。出库带码时按码所在批次**精确扣减**（不走先进先出）。无码出库/转移按先进先出同步移出最早的码；**镜像校准/快照校准**后若某库位×图号件数少于在库码数，按**最早入库的码保留**并记日志（服务端控制台 `[MO 在库索引]`，`GET /api/mo/stock` 可查）。
5. **回写钉钉**：MO 码追加到流水表「备注」（`MO:码1,码2…`），不改钉钉表结构。
6. **看板扫码**（钉钉内）改为走 `/api/scan/resolve`：扫 MO 码打开该图号的产品查询并显示 MO 信息（物料、模号、在库位置），记一笔表单扫产品码位置扫到 MO 码也会换算成图号。
7. **手机摄像头扫码**（没有扫码头时）：PDA 页「📷 摄像头扫码」用手机后置摄像头连续识别二维码/一维码，结果与扫码头输入走同一流程。浏览器只允许 https 页面调摄像头，需设置环境变量 `HTTPS_PORT` 启动（首次自动生成自签证书存 `data/cert/`，HTTP 端口照常可用），手机打开 `https://电脑IP:HTTPS端口/#pda`。
8. **扫码测试码页 `#testcodes`**（设置页 → 库位登记下方「扫码测试码」）：电脑屏幕显示大二维码——已登记启用库位（默认前 12 个，可展开）、已导入 MO 码（带物料名称/图号/模号）；对照表为空时显示样例 `MO261121000001`~`08` 并可「一键导入样例数据」（前 4 条 A000717 左壳体 `92056593(6545、6563)` 模号 R137~R140；后 4 条 A000264 中间箱体 `4570H5` 模号 R131~R134，单据 BC2611210001），另放未导入码 `MO261121999999` 测「未导入 → 选图号」流程。

### 摄像头扫码测试步骤（两台设备：电脑显示码、手机扫）

1. 电脑上用测试数据目录启动（Windows cmd，在项目根目录）：
   ```bat
   set PORT=8793& set HTTPS_PORT=8794& set DATA_DIR=D:\board-test-data& npm start
   ```
   启动窗口会打印「局域网 HTTPS（手机摄像头扫码用）: https://电脑IP:8794/#pda」。用独立的 `DATA_DIR` 不会碰正式台账。
2. Windows 防火墙放行：首次启动弹「允许访问」时勾选专用网络并允许；没弹的话在「Windows Defender 防火墙 → 高级设置 → 入站规则」新建端口规则，放行 TCP 8793、8794。
3. 电脑浏览器打开 `http://localhost:8793/#testcodes`，登记几个库位；对照表为空时点「一键导入样例数据」。
4. 手机连同一 WiFi，浏览器打开 `https://电脑IP:8794/#pda`：提示证书不安全 → 点「高级 → 继续访问」（iPhone Safari：显示详细信息 → 访问此网站）；点「📷 摄像头扫码」→ 允许使用摄像头。
5. 选「入库」，对准屏幕扫一个库位码 → 扫几个 MO 码（应带出物料名称/图号/模号）→ 扫 `MO261121999999` 应提示未导入并要求选图号 → 提交。屏幕调亮，手机离屏幕 20~40 cm。

新增接口：`POST /api/momap/import`（JSON `{text}` 或 xlsx 二进制）、`GET /api/momap?q=`、`PUT /api/momap/:code`、`GET|POST /api/momap/alias`、`GET /api/scan/resolve?code=`、`GET /api/mo/stock`；`POST /api/txn` 新增可选 `moCodes`（件数须等于码数）与 `requestId`（幂等，重复提交返回首次结果并带 `duplicate: true`）；`PUT /api/settings` 支持 `moPattern`。

已知边界：钉钉流水表没有 MO 码列，镜像模式下钉钉端对出库按先进先出重放，与网页端按码精确扣减可能落在不同批次（件数一致，批次停放天数可能不同）；MO 索引以「码数 ≤ 件数」为准自动校正。

## 口径速记

- 记账单元 = 库位 × 批次 × 件数，一库位可混放多批次
- 停放天数 = 今天 − 入位日（入库时间，或转移至该库位的时间）；出库即终止
- 台账只追加不修改，每笔带序号；库存 = 流水重放结果，可审计
- API 保留「全区域快照校准」入口（POST /api/day），需要与传统盘点对账时启用

## 分发包兼容性（低配旧电脑）

- 分发包捆绑 **Node v14.21.3**（官方支持 Win7 SP1 的最后主线，Win7 SP1 → Win11 全线可跑），不再复制开发机的 node.exe（v24 在 Win7/8 与未打补丁的旧系统上会报“动态库缺失/失效”）
- 包内 `node/` 目录附带 VC++ 与 UCRT 运行库 DLL（19 个，来自 Windows SDK Redist 官方 app-local 分发集），旧系统无需安装任何补丁即可启动
- 后端 HTTP 全部走 `node:https`（Node 14 无全局 fetch）；esbuild 打包目标 `--target=node14`
- 真正跑不起来的只剩两类机器：Win7 未装 SP1、32 位系统。前者装 SP1 即可，后者无解（需 64 位）
